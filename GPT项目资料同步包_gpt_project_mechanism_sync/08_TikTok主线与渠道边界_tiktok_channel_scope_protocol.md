# Sales-First 渠道与触点边界

## 当前渠道口径

`已确认`：汾酒的长期主线是可核验销售闭环，不是 `TikTok-only` 或多渠道同时运营。TikTok 是候选内容发现/商品场景展示触点；它是否成为首个试点渠道，取决于当前账号、当地酒类许可、平台政策、年龄/地域要求、承接路径和用户授权。

所有渠道遵循：一个内容生产中心 → 多渠道**受控**分发 → 统一询盘承接 → 统一销售漏斗 → 统一数据反馈。渠道必须服务销售漏斗的明确一步，不能因为平台存在就变成独立运营项目。

## 候选角色与不可推断事项

| 触点 | 可能角色 | 当前不可推断 |
|---|---|---|
| TikTok | 内容发现、场景/兴趣测试 | 可发布、可投放、可导流、可交易。 |
| Instagram / Facebook | 内容复用、品牌信任、社交发现 | 可销售酒类、可自动私信或可投放。Meta commerce channels 不得销售酒类。 |
| WhatsApp Business | 非交易询盘/人工客服候选 | 可作为酒类交易、下单或付款通道；平台政策禁止酒类交易。 |
| Website | 品牌可信度、资料、FAQ、受控 CTA | 已有官网、表单、支付或任何合规资格。 |
| Gmail / Business Email | 后置的低频精准 B2B | 已有联系人处理依据、发送授权或酒类营销资格。 |
| Company Website / Directory / Association | 后置的 B2B company discovery | 可抓取、可保存联系人、可外联。 |

## 渠道启动闸门

每个拟执行动作都要在当前证据中核验：`technical_capability`、`platform_policy`、`local_legal_status`、`project_authorization`、Offer 事实、账号 owner、数据处理/DNC、人工 owner、用户明确授权和停止线。缺任一项为 `BLOCKED`。

## 允许与禁止

在闸门未通过时，只允许内部内容草稿、Offer 资料准备、渠道/账号/政策核验清单、人工 SOP 和低风险分析。禁止公开发布、投放、真实导流、报价、收款、订单承诺、自动消息、抓取绕过、批量联系和规避平台/法律限制。
