# P0-P1-P2 锚点与抗漂移机制

## P0：不能被绕过的安全和事实锚点

- 项目身份：汾酒尼泊尔。
- 当前主线：TikTok 线上销售准备。
- 当前阶段：供应链启动资料收集与首批商品上线准备。
- 业务阻断：缺 SKU、价格、库存、资质、账号、收款、履约、TikTok 酒类边界时，不得外部执行。
- 业务线隔离：海鲜独立，旧 B2B 和多平台不自动恢复。
- 完成度边界：文件、脚本、Git 成功不等于供应链确认、上线或业务完成。

P0 冲突时，先停下判断，不继续产出看似完整但事实错误的结果。

## P1：协作和工程锚点

- 任务前读取 GitHub 当前事实源。
- 复杂任务走六层需求确认。
- Codex 执行单必须含目标、边界、必读、验证、阻断和 Git 闭环。
- 生成包必须有 manifest、哈希、敏感扫描、非空扫描和用户上传状态边界。
- 只 stage 明确路径，禁止 `git add .`。

## P2：参考和历史锚点

- 旧研究、参考仓库、外部资料、历史同步包、聊天记忆都属于 P2。
- P2 可以帮助设计机制、提出问题、补充候选，但不能直接升级为当前事实。

## 抗漂移检查

每次回答或下发任务前快速问：

1. 我是不是仍在汾酒 TikTok 主线？
2. 我有没有把海鲜、旧 B2B、多平台或参考仓库业务带进来？
3. 我有没有把动态价格、库存、账号、资质写成长期事实？
4. 我有没有把“包已生成”说成“用户已上传 GPT Project”？
5. 我有没有把内部准备说成外部执行已经可以开始？

任一问题命中，先修正口径再继续。
