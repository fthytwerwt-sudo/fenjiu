# 协作机制采用对照｜参考机制到汾酒项目

> 本项目只借鉴参考仓库的协作机制，不继承参考项目的业务内容、客户资料、产品信息、绝对路径、账号、任务、结论或秘密。

## 审计边界

- **目标仓库**：`fthytwerwt-sudo/fenjiu`；审计时没有可见提交/分支，本地工作区尚未初始化为 Git 仓库。
- **参考仓库**：`fthytwerwt-sudo/-`；默认分支 `main`，可见入口规则、当前状态锚点、执行日志、规范上传包、清单和多 Agent 路由资料。
- **本地资料**：既有资料含汾酒与海鲜两条业务线、文档脚本、研究 JSON、媒体、QA 和生成物。机制设计只读取其结构和当前可证实的项目边界。

## 采用对照

| 参考机制 | 解决的问题 | 是否适合汾酒项目 | 本项目采用方式 | 是否重写 |
|---|---|---:|---|---:|
| 根目录 `AGENTS.md` + 固定阅读顺序 | 新 Agent 误读入口、混淆事实源 | 是 | 用单项目入口，明确汾酒/海鲜分线与酒类合规闸门 | 是 |
| 短的当前状态/最近执行记录 | 新会话不知道“现在到哪了” | 是 | `CURRENT_STATUS.md` + `EXECUTION_HISTORY.md`，只记已验证事实和阻断 | 是 |
| 规范同步/上传包与 manifest | 交接时带入过多资料或找不到正确包 | 是 | allowlist 同步包、文件索引、Git 状态、manifest、ZIP | 是 |
| 事实源优先级和旧资料降级 | 多份文档互相冲突 | 是 | `SOURCE_OF_TRUTH.md` 规定原始资料、派生产物、状态文档与本地私有资料的层级 | 是 |
| 任务卡与交接模板 | 任务目标、边界、验收和阻断不完整 | 是 | 统一任务/会话/执行报告模板 | 是 |
| 决策记录 | 关键取舍被聊天历史吞没 | 是 | 轻量 ADR，记录机制决定；业务决定另需证据 | 是 |
| 多 Agent 路由与只读探索 | 多人同时改核心文件造成冲突 | 部分适合 | 可并行只读审计；核心状态、事实源和同步包由一个整合者写入 | 是 |
| 深度运行时、特定模型/检索供应链 | 参考项目的专属执行依赖 | 否 | 不引入、不假设本项目已具备 | 不采用 |
| 参考项目的业务指标、素材、历史结论和绝对路径 | 参考项目自身交付 | 否 | 完全排除 | 不采用 |

## 本项目的简化原则

1. 只保留一个默认入口，避免多层重复导航。
2. 同步包只收录“理解项目所需的轻量文件”，不复制业务原件和大文件。
3. 以 `CONFIRMED` / `INFERRED` / `UNKNOWN` / `BLOCKED` / `SUPERSEDED` 明确认识层级。
4. 先做只读审计，再做最小、可验证修改；不把协作机制扩展为未经授权的业务自动化。
5. 对外、合规、平台和真实交易均以人工/书面闸门优先。
