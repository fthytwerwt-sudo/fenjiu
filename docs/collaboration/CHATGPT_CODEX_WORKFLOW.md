# ChatGPT、Codex、Work 与用户协作流程

## 责任链

```text
用户：方向 / 授权 / 最终验收
  ↓
ChatGPT：澄清目标与边界 / 形成可执行任务单 / 审查结果
  ↓
Codex 或 Work：读取事实源 / 实现或整理 / 验证 / 更新状态 / Git 收尾
  ↓
用户与 ChatGPT：复核证据，决定下一轮是否授权
```

## 每轮流程

1. **路由**：确认是汾酒主线、海鲜资料线、协作机制还是本地工具任务；混合时先拆分。
2. **读前检查**：按 `AGENTS.md` 读取入口与状态，检查 Git 状态和任务涉及的事实源。
3. **任务单**：用 `TASK_HANDOFF_TEMPLATE.md` 固定目标、边界、输入、验收和阻断。
4. **执行**：Codex/Work 只在已确认边界内写入；不因“可运行”而越过合规、授权或业务闸门。
5. **验证与回写**：报告实际命令、产物、差异、失败/未测项；更新状态、决策、风险、下一步、执行历史。
6. **同步与交接**：重要节点生成同步包；新会话先复述理解再开始。

## 何时停止并请求判断

- 目标、业务线、事实源或验收相互冲突；
- 需要对外联系、发布、付费、处理个人资料或使用真实账号；
- 合规、平台、主体、SKU/库存/价格等关键条件缺失；
- 发现秘密、私人联系方式或不应上传的材料；
- 需要删除/批量移动原始业务资料。

这不是失败；应记录为 `BLOCKED`，说明已有证据、缺失证据与最小解锁动作。
