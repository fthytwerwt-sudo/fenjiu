# 决策记录｜DECISIONS

本文件采用轻量 ADR（Architecture Decision Record）格式。只有已经被本轮仓库审计或明确确认的机制取舍可标为 `Accepted`；业务选择仍应另行获得用户/合作方确认。

## ADR-0001：以单一入口和短状态文件接续新会话

- **日期**：2026-08-05
- **状态**：Accepted
- **决策**：以 `AGENTS.md`、`PROJECT_ENTRY.md`、`CURRENT_STATUS.md`、`SOURCE_OF_TRUTH.md` 组成固定入口；新会话按规定顺序阅读。
- **原因**：本地资料数量大且包含不同业务线，直接全仓阅读容易造成上下文丢失、误读与重复工作。
- **影响范围**：所有 ChatGPT、Codex、Work 和人工接手任务。
- **替代方案**：仅凭聊天上下文或单个长 README；未采用，因为状态、边界和事实优先级难以保持更新。
- **来源**：2026-08-05 对当前工作区与参考协作机制的只读审计。

## ADR-0002：同步包使用固定 allowlist，不打包业务原件和派生产物

- **日期**：2026-08-05
- **状态**：Accepted
- **决策**：同步包仅复制入口、项目状态、边界、决策、风险、下一步、事实源地图、协作模板、执行历史和构建脚本；业务原件只在索引中被定位。
- **原因**：同步包应让新会话快速理解项目，而不是复制大文件、媒体、缓存、线索或可能敏感资料。
- **影响范围**：`scripts/build_project_sync_pack.py`、`project_sync/latest/`、`dist/`。
- **替代方案**：全仓打包；未采用，因为会带入大量无用文件、可能的隐私/秘密和过期派生产物。
- **来源**：当前工作区规模审计，以及参考仓库的“规范上传包 + manifest + 当前入口”机制。

## ADR-0003：汾酒与尼泊尔海鲜资料线分开建模

- **日期**：2026-08-05
- **状态**：Accepted
- **决策**：本仓库可存放两条资料线，但默认项目入口只服务汾酒；海鲜资料必须通过显式任务和独立原始文件进入。
- **原因**：二者有共同的尼泊尔渠道/供应链主题，但产品、合规、客户、SKU 和商业结论不可互推。
- **影响范围**：入口文档、事实源地图、任务交接与后续生成资料。
- **替代方案**：合并为同一事实库；未采用，因为会提高业务混淆与错误复用风险。
- **来源**：当前目录和文件名称的只读审计。

## ADR-0004：线索库和本地凭据保持本地受控

- **日期**：2026-08-05
- **状态**：Accepted
- **决策**：`.env`、带凭据提示的本地文件、`research_channels.json`、缓存、媒体和 QA/渲染产物不进入 Git 和同步包。
- **原因**：满足最小披露、可恢复性和仓库卫生要求；`research_channels.json` 含公开联系方式与线索字段，仍不作为默认公开资料。
- **影响范围**：`.gitignore`、同步包排除策略和后续 Git 操作。
- **替代方案**：依赖人工每次挑选；未采用，因为人为遗漏风险高。
- **来源**：2026-08-05 本地文件与字段结构审计。
